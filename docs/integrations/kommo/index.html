Kommo Integration

What the AI can do​

Summary​

Kommo Integration connects Kommo CRM with Newo Platform.

It enables:

  • OAuth 2.0 connection setup for a customer-owned private Kommo integration or a Newo-managed public integration.
  • Contact lookup, contact creation, and contact update by phone or email.
  • Lead creation, existing lead selection, and lead stage updates in a configured Kommo pipeline.
  • Conversation notes, follow-up tasks, and existing-client context from finished Newo sessions.
  • Automatic token refresh and retry for Kommo API requests.

This integration is designed for implementation teams and CRM operators who need Newo conversations to create and maintain Kommo CRM records after calls, chats, or outbound campaigns.

Common use cases​

  • When a project is published with a Kommo OAuth code -> Newo exchanges the code, stores tokens, syncs pipelines, and syncs stages.
  • When a Newo session ends with enough contact data -> Newo finds or creates a Kommo contact and emits kommo_contact_ready.
  • When lead features are enabled -> Newo classifies the conversation outcome, selects or creates a Kommo lead, and emits kommo_lead_ready.
  • When lead notes are enabled -> Newo writes a structured conversation note to the Kommo lead timeline.
  • When pipeline updates are enabled -> Newo moves the lead to the selected pipeline stage unless existing-lead preservation skips it.
  • When follow-up tasks are enabled -> Newo creates a Kommo task for the lead responsible user when the session outcome warrants follow-up.
  • When existing client history is enabled -> Newo looks up a caller before or during the conversation and injects CRM context into the prompt.

Features at a glance​

Lead selection and creation✅Selects existing /leads?filter[id]={ids}&with=tags; creates /leads when no suitable lead exists.
Lead stage update✅Updates /leads/{id} with pipeline_id and status_id.

Follow-up tasks✅Creates /tasks linked to the lead and assigned to the lead responsible user.

Multi-location routing❌No location-resolution flow exists in this integration.
Booking, availability, cancellation❌Kommo is used as CRM storage; scheduling requires another integration.
Webhooks from Kommo❌The integration is session-driven and does not define Kommo webhook flows.

Before You Start​

Before installation:

  • Active Kommo workspace.
  • Kommo admin access with permission to create integrations and approve OAuth access.
  • Newo Builder access with permission to edit customer attributes and run Publish All.
  • A Kommo pipeline where Newo-created or Newo-updated leads should be stored.
  • OAuth redirect URI registered in Kommo and configured in Newo. If the Newo attribute is empty, the integration uses https://static.newo.ai/auth.html.

Required Newo attributes for first authorization:

Setup​

Create the Newo project​

If this project already exists in Newo Builder, skip this subsection and continue with the integration-specific settings below.

  1. In Newo Builder, open the projects list and click Create Project (or Create New Project from the top-right menu).

  1. Fill IDN and Title. The exact names do not matter; use any clear names your team will recognize.
  2. In Registry, choose the release channel:
    • staging — the newest module fixes appear here first. Use it when you need the latest fix, but expect possible unfinished changes.
    • production — the final stable version for live projects.
  3. In Module, select the module for this integration.

5. Leave Module version on Latest version unless support tells you to pin a specific version, then click Create.

3.1 Step 1 — Generate Credentials in Kommo​

Private Integration​

Use this method for most customer installs.

  1. In Kommo, open Settings.
  2. Go to Integrations & channels -> Integration marketplace.
  3. Click Create integration.
  4. Set the redirect URL to https://static.newo.ai/auth.html, or to the exact redirect URI your Newo project will use.
  5. Select Allow access: All.
  6. Save the integration with a clear name such as Newo.
  7. Open Keys and scopes.
  8. Copy the Integration ID into kommo_client_id.
  9. Generate and copy the Secret key into kommo_client_secret.

Screenshots for the operator path are stored in this directory:

  • screenshots/kommo-sidebar-settings.png

If the secret key is regenerated later, Kommo invalidates authorizations tied to the old secret. Update kommo_client_secret, generate a fresh OAuth code, and publish again.

Public Integration​

Use Public Integration only when the Newo implementation team confirms that the shared Newo Kommo app is available for the workspace. In this mode Newo fills and hides the shared kommo_client_id and kommo_client_secret, but the customer must still configure:

  • kommo_subdomain
  • kommo_redirect_uri
  • kommo_oauth_code
  • kommo_pipeline_id after pipeline sync

3.2 Step 2 — Connect in Newo Platform​

  1. Open Newo -> Projects.
  2. Create or open the project that uses module kommo_integration.
  3. Open Attributes -> Customer.
  4. Fill the required OAuth attributes.
  5. In kommo_oauth_code, open the generated authorization link.
  6. Approve access in Kommo.
  7. Copy only the code= value from the redirect URL.
  8. Paste it into kommo_oauth_code.
  9. Click Save + Publish All.
  10. After publish, confirm kommo_last_init_error is empty and kommo_pipeline_id has possible values.
  11. Select the target pipeline and publish again to sync stages for that pipeline.

On publish, the integration automatically:

  • registers or updates all Kommo customer attributes under Module - KommoIntegration;
  • creates kommo_connector for HTTP calls if missing;
  • creates a hidden setup persona and system actor used for setup requests;
  • exchanges a one-time OAuth code or refresh token when present;
  • clears kommo_oauth_code after a successful authorization-code exchange;
  • clears kommo_last_init_error on successful InitFlow HTTP callbacks;
  • syncs pipelines from /leads/pipelines;
  • syncs stages from /leads/pipelines/{pipeline_id}/statuses;
  • generates default stage-selection rules when kommo_pipeline_decision_rules is blank.

How to use the integration​

This integration is event-driven. It does not expose user-facing booking tools. It listens for Newo session and setup events, calls Kommo, and writes results back into CRM.

4.1 How the Integration Works​

Where to test​

Testing can be done through:

  • Newo conversation interface for chat or voice sessions.
  • A test persona with phone and email values.
  • Kommo CRM UI for contacts, leads, notes, stages, and tasks.
  • Unit tests under test/kommo/.

How to test that everything works​

To test authorization​

  1. Fill kommo_subdomain, kommo_client_id, kommo_client_secret, and kommo_oauth_code. Fill kommo_redirect_uri only when the Kommo app uses a custom redirect URL.
  2. Click Publish All.
  3. Verify kommo_oauth_code becomes empty.
  4. Verify kommo_last_init_error is empty.
  5. Verify kommo_pipeline_id has possible values from Kommo.
  6. Select the pipeline and publish again.
  7. Verify kommo_pipeline_stages contains stage JSON.

To test post-session contact sync​

  1. Run a test session with a phone number or email.
  2. End the session.
  3. Verify Kommo contact lookup runs.
  4. Verify a contact is created when no matching contact exists.
  5. Verify existing contact phone/email values are preserved when the contact is updated.

To test lead processing​

  1. Enable kommo_update_pipeline.
  2. Select kommo_pipeline_id.
  3. Run a test session with clear sales intent.
  4. Verify a lead is selected or created.
  5. Verify kommo_target_stage_id is stored on the persona.
  6. Verify the lead is moved unless existing-lead preservation skips it.

To test notes​

  1. Enable kommo_enable_lead_notes.
  2. Run a session with summary, actual result, and transcript.
  3. Verify the lead timeline has a common note.
  4. If kommo_crm_language is set, verify the note text is translated while phone numbers, emails, URLs, and dates are preserved.

To test tasks​

  1. Enable kommo_enable_follow_up_tasks.
  2. Use an inbound session where follow-up is clearly needed, or an outbound session that passes hardcoded filters and optional LLM gate.
  3. Verify a task appears on the lead.
  4. Verify the task is assigned to the lead responsible_user_id.

If no action occurs​

  • Check whether the relevant feature flag is enabled.
  • Check kommo_last_init_error after setup.
  • Confirm kommo_redirect_uri exactly matches the Kommo app redirect URL, or that Kommo is configured with the default https://static.newo.ai/auth.html.
  • Confirm kommo_pipeline_id is selected and kommo_pipeline_stages is populated.
  • Confirm the session payload has at least one of transcript, summary, or actualResult.
  • Confirm the session payload or persona has a phone number or email.
  • For outbound tasks, check category, conversationEndedReason, sessionType, and isLead; hardcoded filters skip voicemail, busy, no-answer, missing reason, no-conversation summaries, non-lead calls, and session types without [L].

Note: This integration performs real operations in Kommo. Test in a safe workspace or with test contacts before enabling it for production traffic.

FAQ​

Q: Why does kommo_oauth_code disappear after Publish All? A: That is expected. Kommo OAuth codes are single-use, so the integration clears the code after the first successful Publish All.

Q: When is kommo_last_init_error cleared? A: It is cleared after a successful setup publish. If setup fails, the setting keeps the latest setup error so support can see what went wrong.

Q: Why can OAuth fail with Redirect URI is not associated with client? A: The redirect URL in Newo Builder must exactly match the redirect URL registered in the Kommo integration app. After changing it, generate a fresh OAuth code and click Publish All again.

Q: Does this integration use Kommo long-lived tokens? A: No. It uses OAuth authorization code and refresh token flow through /oauth2/access_token.

Q: Will Newo create duplicate leads? A: Lead handling first checks lead IDs embedded on the contact. It prefers a lead tagged with kommo_lead_tag or kommo_outbound_lead_tag, then falls back to the first returned lead. If no lead is available, it creates one.

Q: Why did an existing lead not move to the selected stage? A: If kommo_skip_pipeline_update_for_existing_leads is true, PipelineFlow skips existing leads to preserve manually managed Kommo pipeline and stage values.

Q: Why did an outbound call not create a task? A: The integration skips follow-up tasks for voicemail, busy/no-answer calls, empty summaries, and sessions that were not classified as leads.

Q: Can the caller schedule appointments through this integration? A: No. Kommo Integration is CRM-focused. Booking and availability require a separate scheduling integration.

Limitations​

  • No direct Kommo webhook ingestion is configured.
  • No calendar scheduling, availability lookup, booking cancellation, or rescheduling is implemented.
  • No multi-location routing is implemented.
  • Stage selection depends on synced stage names and the quality of kommo_pipeline_decision_rules.
  • Follow-up task creation requires a Kommo lead with responsible_user_id; otherwise TaskFlow skips task creation.
  • OAuth setup depends on exact redirect URI matching; stale OAuth codes must be regenerated.
